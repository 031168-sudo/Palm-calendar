Календарь в духе Palm Tungsten T3 Date Book / Agendus: события с типом (звонок, встреча, задача, выезд, письмо, событие), привязанные
к людям из телефонной книги, — «лёгкая CRM» (история контакта, итоги, статистика). Kotlin + Compose Multiplatform. Android синхронизируется
с Google Календарём, iPhone — с календарём Apple (EventKit). Владелец — Андрей (общение на русском, на «ты»).

Репозиторий: https://github.com/031168-sudo/Palm-calendar (публичный). Ветка `main`.

## Android: календарь и данные

- **События живут в системном календаре Android** (CalendarContract → синхронизация с Google).
  Тип/контакт/номер — в Room (`data/LinkDb.kt`, БД `palmdate.db` v5: links, contact_phone, outcomes,
  mail_links, trip_files) **и** дублируются меткой в описании события `[palm:t=TYPE;c=lookupKey;p=phone;m=mail]`
  (`CalendarRepository.Marker`) + строка «Итог: …» — чтобы всё восстанавливалось. На iPhone — та же метка в заметках EventKit.
- Повторяющиеся: DURATION вместо DTEND; весь день — в UTC; напоминания весь день — отрицательные минуты.
  **Android пересчитывает разы, только если в update есть DTSTART** — передавать всегда.
  Изменения повтора/времени и удаление «этот и следующие» — «с открытого раза»: старая серия получает UNTIL,
  с этого раза создаётся новая. При смене времени повторяющегося — выбор «только этот раз / этот и следующие / вся серия».
  Удаление одного раза — исключение со STATUS_CANCELED.
- EventType: CALL, MEETING, TASK, TRIP, MAIL, OTHER; BIRTHDAY — только дни рождения из контактов.
- Поворот/складывание не пересоздают экран (`android:configChanges`). Широкий экран (≥600dp): карточка колонкой справа
  (книжка — по сгибу); «ноутбук» — сверху календарь, снизу карточка и кнопки.

## Выезд (тип TRIP — «Выезд» / «Trip»)

Один тип на всё, куда едешь: театр, кино, поездка, командировка (иконка — метка места).
- Адрес — поле «Место» системного календаря (`CalendarRepository.location/setLocation`, `PalmEvent.place`);
  поле адреса в «Новое» и в карточке, кнопка «Маршрут»; можно взять адрес из контакта.
- Тап по иконке выезда с адресом в списке → открывается маршрут (карты); без адреса — как у других типов.
- Документы (билеты, посадочные, брони): `data/TripFiles.kt` копирует файл во внутреннюю память
  (`files/trips/<id>/`), таблица `trip_files` (подпись: Билет/Посадочный/Бронь/Документ), открытие через
  FileProvider `${applicationId}.files`; входят в резервную копию (base64, `Backup.kt`).

## Адрес встречи

В карточке встречи строка «Адрес» есть всегда: свой адрес события (поле «Место» календаря, `PalmEvent.place`) важнее адреса
контакта; если своего нет — берётся адрес контакта; если нет ни того ни другого — «добавить адрес…». Стрелка у адреса открывает
выбор: адреса контакта (как раньше, запоминается для контакта) и «Добавить/Изменить свой адрес…». Свой адрес хранится отдельно (`data/OwnAddresses`, prefs `own_address`, входит в резервную копию), поле «Место» — это
действующий адрес: выбор адреса контакта очищает «Место», но свой адрес остаётся в списке (его можно выбрать снова или «Изменить свой адрес…»). Маршрут по тапу на иконку встречи — тоже `place ?: contact.address`. У звонков адрес контакта показывается как раньше.

У задачи и обычного события («Событие», в т.ч. чужие из Google без типа) тоже есть строка «Адрес» — просто свой адрес в поле «Место»
(без выбора из контакта): тап по адресу — карты, стрелка — изменить; у «Событие» тап по иконке открывает маршрут, у задачи иконка отмечает выполнение.

Порядок карточки: строки события (когда, календарь, телефон, заметка, адрес) → главные кнопки («Маршрут»/«Позвонить»…, «История») → «Документы» → итог → повтор → напоминания.

Кнопки в ряду («Позвонить»/«Написать»…, «Маршрут», «История») все белые (не залитые). «Маршрут» один на карточку: показывается, если есть адрес
(`place ?: адрес контакта`), в том же ряду; у встречи/выезда/задачи/события он же заменяет главное действие, дублей нет.

## Значки во второй строке события (`EventLine` в `DayScreen.kt`)

Порядок слева направо: колокольчик → документы → текст. Колокольчик (`PalmEvent.hasAlarm`, из `Events.HAS_ALARM`):
обычный — есть любое напоминание, перечёркнутый — нет; у дней рождения из контактов (`hasAlarm = null`) не рисуется.
Значок документов — `PalmEvent.hasFiles`.

## Часы в днях и неделе

В виде «День» и «Неделя» всегда 24 часа. Рабочие часы (Настройки → Вид, `dayFrom..dayTo`) — обычный серый пунктир,
остальные — бледно-зелёный пунктир (`Palm.offRule`). Пробовали насыщенный зелёный с заливкой и терракотовый — Андрей вернул первый,
бледно-зелёный вариант (build-76).

## Длительность событий в «Дне»

Между метками часов и плашками — дорожки (`LaneDecor`/`laneDraw` в `DayScreen.kt`): у каждого события цветная вертикальная линия от начала до конца
с точками на концах; пересекающиеся события — в соседних дорожках (до 4). Плюс бледная заливка того же цвета на ширину строк события (накладываясь,
цвета темнеют); включается переключателем «Заливка длительности событий в «Дне»» (Настройки → Вид, `AppSettings.durationBand`, по умолчанию включена).
События «на весь день» закреплены над часами (отдельный блок до ~132dp, дальше листается сам) и не прокручиваются вместе с днём.
Каждая строка (пустой час/событие) рисует свой кусок: время строки t..следующая строка → доли высоты. Неделю не трогали.

## Свои повторения («Настроить…», как в Google Календаре)

Рядом с кнопками повтора (не заменяя их) — «Настроить…»: окно `ui/RepeatDialog.kt`: каждые N дней/недель/месяцев/лет; для недель — кружки дней; для
месяца — «каждое 14-е число» / «каждую вторую среду» / «каждую последнюю среду»; окончание: никогда / в дату / после N раз. Результат — обычный RRULE
(`FREQ;INTERVAL;BYDAY;BYMONTHDAY;COUNT;UNTIL`), его понимают Android и Google. Логика — `model/Repeat.kt` (`RepeatSpec.parse/toRrule/describe`); правила из Google
разбираются обратно и показываются словами («Каждые 2 недели по пн, ср»); что не умеем (BYSETPOS и т.п.) — «Своё правило». Простые правила пишутся как кнопки
(`FREQ=WEEKLY`, `FREQ=MONTHLY`). UNTIL: у «весь день» — дата, у обычных — конец дня в UTC. Проверки: `LogicTest.customRepeatRules`, на эмуляторе `RepeatRuleTest`.
Известное ограничение: сдвиг времени серии (`setTime`) убирает COUNT из правила.

## Почта (категория «Письмо»)

Только через почтовую программу телефона (Gmail, Яндекс Почта…), без паролей. Встроенную почту (IMAP/SMTP, JavaMail)
убрали в build-75 по просьбе Андрея. «Написать» открывает программу с адресом (выбор программы с галочкой «всегда»;
сброс — в Настройки → Почта); «Ответить» — при создании «от кого + что искать», при открытии запускает программу
и копирует строку поиска; по возвращении вопрос «Письмо отправлено?» → итог «Отправлено». Код: `ui/MailUi.kt`
(`MailHost`), `data/MailApps.kt`. Поля `MailInfo` (messageId, folder, hasDraft…) и таблица `mail_links` остались
в базе для совместимости со старыми копиями, но больше не используются.

## Файлы в событии

У любого события (кроме дней рождения из контактов) в карточке есть «Документы» и «Добавить файл»; у выезда — с подписями
(Билет/Посадочный/Бронь/Документ), у остальных — просто имя файла (подпись пустая). Хранение то же, что у выезда (`TripFiles`).

## Время события: начало и конец

В окне времени (карточка) и в шаге «Когда» («Новое») есть строки «Начало» и «Конец» с − / + (шаг из настроек); «Конец» меняет длительность
(не меньше 5 мин), начало не двигается; кнопки-пресеты длительности остались. Длительность 0 (событие 12:00–12:00 из Google) раньше ломала
«изменить время» у повторяющихся — Android не принимает DURATION=P0S; теперь везде `secDuration()` (минимум 1 с).

Если таблица Instances отдаёт конец = началу (на телефоне Андрея так было у «Теннис»/«Показания» — Google показывал верно, в самом событии DURATION
верная), `eventsBetween` берёт длительность из события (DTEND/DURATION). Проверка «календарь принял время» через Instances убрана — она ложно срабатывала.
Если у повторяющегося события в Instances один раз нулевой длины (серия «слетела»: Google показывает повтор, у нас нет), `eventsBetween` один раз за запуск
перезаписывает начало/длительность/правило (`touchSeries`) — Android заново строит разы.
В тексте ошибки смены времени остаются сырые поля события (`eventDump`).

## День: адаптивные строки названия
В «Дне» (только он; Повестка/Неделя/Месяц не трогаем) число строк названия зависит от числа событий со временем: ≤3 → до 3 строк, 4–6 → до 2, 7+ → 1 (`titleLines` в DayBody, параметр `EventLine.titleLines`). Короткие названия не растягиваются. В шапке карточки события название показывается целиком (без maxLines). Пороги выбраны на глаз, подстроить по скриншотам.

## Выбор даты и времени по тапу (окно «Когда» и шаг «Когда» в «Новое»)
Плюсы/минусы/стрелки остались (настройка шагом). Тап по самой дате — стандартный календарь (`DatePickDialog`), тап по времени начала или конца — круглый выбор времени, 24 ч
(`TimePickDialog`, оба в `ui/Pickers.kt`). Конец по часам меняет длительность (`minutesForEnd`: конец не раньше начала, иначе на следующий день); начало при этом не двигается.

## Шапка «Недели»
В «Дне» и «Повестке» в шапке полоска дней недели; в «Неделе» её нет (видна вся неделя) — только стрелки ‹ › сдвига на неделю, как в «Месяце»/«Годе» (`showStrip`/`byWeek` в `shared/.../ui/MainFrame.kt`).
